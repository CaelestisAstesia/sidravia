# 命名与模块约定

本约定是代码命名和职责划分的统一依据。修改现有代码时优先消除歧义，不为形式整齐批量改名。稳定的命令、IPC/JSON 字段、配置键、协议标识、数据路径和发行资产属于外部契约，不能随内部整理改变。

## 领域术语

| 术语 | 含义与边界 |
| --- | --- |
| Configuration | 用户保存的认证配置，不是一次认证执行 |
| Institution Profile | 机构提供的公共协议参数，不包含用户凭据 |
| Credential | 认证秘密及其必要身份信息，不属于公共诊断快照 |
| Session | 持有认证意图、重试和网络绑定选择的会话；可以经历多次协议 Run |
| Supervisor | 管理会话集合、单活准入和快照分发，不执行报文交换 |
| Run | 一次协议执行，拥有该次执行的 socket、协议状态及清理 |
| Observer | 观察并报告事实，不决定会话意图 |
| Snapshot | 某一时点的事实或状态值；跨边界按约定复制，不代表实时共享可变状态 |
| Revision / Generation | Revision 标识快照更新；Generation 区分一次次运行，不能互换 |

优先沿用这些已有术语。`State` 表示状态机中的状态，`Status` 可表示一次查询的汇总结果，不对现有公共契约做机械替换。区分原始错误原因、稳定机器码和用户消息，不让一个名称混指三者。

## 标识符与文件

- 使用英文和所属语言的常规形式：Go 包名小写、标识符 MixedCaps；Dart 类型 UpperCamelCase、成员 lowerCamelCase、文件 lower_snake_case；Python 模块/函数/变量 snake_case、类 UpperCamelCase。Go 文件使用 lower_snake_case，平台文件沿用 `_linux.go`、`_windows.go` 等构建约定。
- Go 的通用缩写保留惯用大小写，如 `ID`、`URL`、`HTTP`、`JSON`、`UDP`、`IPv4`；线协议的 `KA1`、`KA2` 等沿用协议文献术语，并在附近说明语义。不改外部序列化字段的大小写。
- 名字描述业务含义和作用域，不描述实现时代或主观评价。避免无依据的 `New`/`Old`/`V2`、`Common`、`Utils`、`Helper`、`Manager`；构造函数 `New`、真实协议版本和有明确职责的既有名称不受此限制。
- 短作用域可使用 `ctx`、`err`、`id`、索引及简短接收者；跨函数或长期状态应能直接读懂。不要为展开缩写牺牲可读性，也不要在包名和类型名之间机械重复领域词。
- 文件按用例、状态所有权或平台边界组织，同名测试放在 `_test.go`；文件拆分不产生新状态所有者。只在真实模块契约、平台边界或替换点创建接口，不为改名增加包装层。

## 状态与动作

- 状态字段和类型用名词，状态值描述所处阶段，动作名用动词：例如 `Snapshot`、`ApplySystemNetworkSnapshot`、`Restart`。`has`/`is`/`can` 等布尔前缀仅在能澄清语义时使用；避免否定叠加。
- 锁的名称和注释说明保护范围；存在多个不同锁时使用 `operationMu` 等可区分名称，只有一个明显保护对象的锁可保留 `mu`。共享状态注明权威所有者；必要时说明锁顺序和哪些调用必须在解锁后执行。
- channel 名称说明传递的消息或生命周期事件；关闭信号与“已退出”的确认必须可区分，例如 `stopForwarding` 与 `forwardDone`。生命周期动作应能看出取消与等待的责任，不用模糊缩写隐藏清理语义。
- `Snapshot`、`Clone`、`Validate`、`Parse`、`Build` 等名称应对应实际行为：快照的复制/并发边界、校验是否有 I/O、解析与报文构造的副作用必须清楚。已有例外先准确注释，不在命名任务中顺带改变行为。

## 四层职责

| 模块 | 拥有的职责 | 不负责的决定 |
| --- | --- | --- |
| `environment` | 采集、规范化系统网络事实，形成有版本的快照 | 不选择认证策略，不启动认证 |
| `supervisor` | 会话集合、单活准入、网络快照分发和订阅 | 不持有协议交换状态 |
| `session` | 意图与状态机、绑定选择、重试调度、Run 生命周期 | 不编解码具体协议报文 |
| `protocol` / `d520` | 协议契约及单次执行、报文编解码、socket 和有界清理 | 不持久化账号、不接管产品重连和系统网络配置 |

协议内部为维持当前 Run 所需的心跳、交换重试和恢复仍属于协议；Session 的重试负责下一次 Run。两者不能只因都叫“重试”而合并。平台网络事实采集留在平台文件，核心策略不按平台分叉。

## 注释与测试

注释说明契约、原因、单位、所有权、取消和安全边界，避免复述语句或保留失效的未来计划。公开声明的文档以声明名开头；协议字段和布局说明保留与规范逐字节核对的能力。

Go 测试使用 `Test<对象或操作><场景或结果>`，表驱动子例描述输入条件或领域结果。测试证明行为、领域规则、公开契约和已识别的生命周期风险，不依赖无关的私有名称或文件位置。内部改名同步引用，不为统一风格删除断言、扩大生产接口或新增镜像实现的测试。

## 应用方式

新增代码遵循本约定；整理旧代码时按模块小批实施，每次说明原名称的具体歧义和职责边界，验证并设置提交回滚点。已清楚的名称保留；涉及公共契约或行为改变时，单独说明兼容性与验证范围。
