# ADR 0021：CLI 采用轻量的逐行交互

**状态：** Accepted

## 背景

CLI 已经使用 Cobra 管理命令树、使用 termenv 负责安全着色，并具有确定性的中文帮助、
状态和列表输出。接下来的持久配置管理需要更舒服的输入体验，但 Sidravia 没有持续刷新
的仪表盘、日志监控、复杂多窗格或高频键盘导航需求。为这些场景提前引入全屏 TUI 会增加
渲染状态、终端恢复、重定向行为和跨平台测试成本，却不能改善核心配置流程。

## 决定

当前大版本继续使用 Cobra 与 termenv，不引入 Bubble Tea、Huh、Lip Gloss、表格框架或
其他全屏 TUI 依赖。交互维持短生命周期、逐行、可取消的命令流程。

本决定替代 ADR 0014 中“网络选择契约稳定之前不加入引导式设置”的时间顺序：持久配置
管理可以在网络修正之前加入轻量逐行向导，但不因此引入通用表单框架或全屏 TUI。ADR
0014 的其余呈现和终端安全规则不变。

当持久 Configuration/Credentials 入口需要引导时，在 `internal/cli` 的呈现边界内增加
少量私有构件，例如标题、字段组、成功/警告文本、普通文本输入、枚举选择和确认。它们
复用现有终端能力判定、动态文本清理和密码隐藏输入，不把交互状态、终端类型或样式对象
泄漏给业务层。

所有核心操作仍必须有明确的非交互参数形式。stdin/stdout 被重定向时，不隐式进入向导，
也不输出 ANSI、光标控制或布局填充；自动化调用可以绕过交互层。向导只负责收集输入并
调用与普通命令相同的 typed 用例。

## 结果

- 当前目标是让帮助、输入、确认和结果更好看、更一致，而不是建设终端应用框架。
- 依赖、二进制体积和终端状态管理保持小而清晰。
- 若以后出现真实的多视图监控或复杂交互需求，可以以独立产品切片重新评估全屏 TUI；
  未来 GUI 不要求先建设 TUI。
- 本决定补充 ADR 0014；其中已经接受的重定向安全、`NO_COLOR`、控制字符清理和固定中文
  呈现规则保持不变。
