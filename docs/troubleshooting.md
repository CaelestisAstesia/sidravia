# 常见问题与反馈

先记录当前状态、错误提示和发生时间，再按现象排查。日常操作见[使用指南](guide.md)，需要命令行时再看[高级使用](advance.md)。

## 无法连接

按下面的顺序检查：

1. 当前网络是否属于已支持的吉林大学 Dr.Com 5.2.0 D 认证环境。
2. 账号、密码是否正确，其他认证客户端是否已经退出。
3. 认证网卡是否连接，明确指定的 IPv4 是否仍属于该网卡。
4. VPN、代理或 TUN 是否改变认证服务器的路由。可暂停相关功能作对照，长期配置根据实际网络确定。
5. 在「设置 → 连接与诊断」刷新网络诊断，查看目标、网卡与错误提示；按需要执行有限 IP 探测。

当前吉林大学 Profile 使用 UDP `61440`，本地也使用固定端口。出现端口占用提示时，核对实际绑定地址与其他认证程序，不要仅凭端口号猜测原因。

超时、协议响应异常和服务器拒绝需要分别判断。一次失败不能证明问题在账号、程序或网络；也不要通过随意填写 override 尝试修复未知问题。

## 认证成功，但网页打不开

认证成功表示认证协议建立了连接，不保证 DNS、代理或互联网访问正常。先对照域名解析、代理设置与实际访问情况，避免仅凭网页失败反复修改账号或协议参数。

网络诊断与有限 IP 探测也只证明各自检查到的结果，不代表完整网络可用。

## 没有自动登录或自动重连

分别检查「启动时自动登录」「自动重连」「开机自启」。自动登录在后台启动时评估，开启开关本身不立即连接；自动重连修改在下次连接生效。

开机自启指当前用户登录 Windows 时启动程序。「仅后台」模式看不到 GUI 是预期行为；希望使用 GUI 时选择「启动到托盘」。已经运行另一模式时，先正常退出再切换。

如果状态提示需要人工处理，先处理错误，再手动连接。三项设置的区别见[使用指南](guide.md#自动连接与开机自启)。

## 关闭窗口后仍然在线

默认关闭窗口会隐藏到托盘。需要结束程序和连接，在托盘菜单选择「退出 Sidravia」；也可以在设置里调整关闭主窗口的行为。

## 学校公告无法显示

公告依赖学校网站可达与 WebView2 Runtime。先检查学校网页是否能在浏览器打开；网页可达但公告窗口失败时，检查 WebView2 Runtime，并保留窗口提示供反馈。

公告显示失败与认证失败分别判断。Windows 通知未弹出时，也检查系统通知设置，不要仅凭没有通知判断连接失败。

## GUI 与 ctl 提示模式冲突

GUI 使用 desktop 后台，ctl 认证命令使用 headless 后台。两种模式互斥，不会自动接管对方。

- GUI 切换到 ctl：在托盘选择「退出 Sidravia」，再启动独立后台。
- ctl 切换到 GUI：执行 `sidraviactl daemon stop`，确认停止后再打开 GUI。

切换会结束原连接。`daemon status` 可只读查看后台状态，其余认证和配置命令不能作为已打开 GUI 的控制台。具体步骤见[高级使用](advance.md#与-gui-配合使用)。

## GUI 提示多个配置或会话关系不明确

GUI 暂不支持多配置选择，也不会猜测操作对象。多配置提示需要先退出 GUI，再按[高级使用](advance.md)通过 ctl 的 `config list` 和 `config show ID` 核对配置。确认只保留一份需要的配置后，再停止独立后台并打开 GUI。删除配置会删除其中的账号与凭据，不要直接删除配置文件来消除提示。

如果只有一份配置却提示会话关系不明确，先正常退出并重新打开 GUI。会话记录只属于本次后台，不会随后台重启保留；反复出现时按下文反馈，不要为了清理运行状态删除账号配置。

## 提示存储未受保护

密码以明文保存在本地文件，依赖操作系统文件权限保护。无法建立保护时，程序会要求确认。先检查数据位置和权限；确认选项不提供加密，也不能修复权限。详见[数据与隐私](privacy.md)。

## 后台未启动、包不完整或版本不兼容

确认发行包已经完整安装或解压，GUI、ctl、后台和配套文件来自同一个版本。不要单独替换某个 EXE；已有旧后台时先正常停止，再运行新版本。

ctl 的只读列表和诊断不会为了查询自动启动后台。需要命令行操作时，先显式运行 `sidraviactl daemon start`；GUI 则通过自己的启动流程管理核心。

## 反馈问题

通过 [Issues](https://github.com/CaelestisAstesia/sidravia/issues) 提供以下信息：

- 完整版本、安装版或便携版、是否自行构建。
- 操作系统版本，以及 GUI 或 ctl 使用模式。
- 有线或无线，是否运行 VPN、代理、TUN 或其他认证客户端。
- 发生时间、复现步骤、预期结果与实际状态或错误码。
- 正常与异常情况的差别，以及可复现时的诊断摘要。

GUI 在「连接与诊断」复制诊断信息。ctl 模式可导出结构化摘要到尚不存在的文件：

```powershell
.\sidraviactl.exe diagnostics export --output .\sidravia-diagnostics.json
```

不要仅为导出而在连接故障现场立即切换模式；模式切换会结束当前连接。GUI 摘要与 ctl 导出的内容形式不同，按实际使用模式提供即可。

摘要使用限定字段，不是完整日志。分享前检查内容和截图，遮住账号等个人信息。不要提交密码、`configurations.json`、原始认证报文或未经检查的 TRACE 日志。
