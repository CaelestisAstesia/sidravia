# 常见问题

## 无法连接

先看首页的错误提示，再检查：

- 是否在吉林大学 Dr.Com 5.2.0 D 网络环境中。
- 账号、密码是否正确，其他认证客户端是否已退出。
- 所选网卡是否连接，指定的 IPv4 是否还在使用。
- 是否开启 VPN、代理或 TUN。可以暂时关闭后再试，看看是否影响认证路由。

仍然失败时，在「设置 → 连接与诊断」刷新诊断，记下错误码和发生时间。超时、服务器拒绝、协议响应异常可能有不同原因，反馈时请保留具体提示。

吉林大学配置的服务端和本地端口均为 UDP `61440`。提示占用时，检查实际绑定地址及其他认证程序。

## 认证成功，但网页打不开

继续检查 DNS、代理和网络访问。认证成功只说明认证连接已建立；网络诊断和 IP 探测也不能替代实际网页访问。

## 没有自动登录或自动重连

打开自动登录开关后，下次后台启动时才会自动认证；自动重连设置在下次连接生效。开机自启只负责启动程序，三项设置的区别见[使用指南](guide.md#自动连接与开机自启)。

如果首页提示需要人工处理，先解决相应错误，再连接。

## 关闭窗口后仍然在线

默认会隐藏到托盘。选择托盘菜单的「退出 Sidravia」才能退出并断开；关闭行为也可以在设置中更改。

## 学校公告打不开

先试试浏览器能否打开学校网页。浏览器正常、公告窗口却失败时，检查 WebView2 Runtime。通知不显示时，检查 Windows 通知设置。

## GUI 与 ctl 提示模式冲突

- GUI 切换到 ctl：先从托盘退出 Sidravia，再启动命令行后台。
- ctl 切换到 GUI：先执行 `sidraviactl daemon stop`，再打开 GUI。

切换会断开连接。GUI 运行期间，ctl 只有 `daemon status` 可以跨模式查询后台状态。

## 提示多个配置或会话关系不明确

GUI 暂不支持多配置选择。先退出 GUI，再用 ctl 的 `config list`、`config show ID` 核对配置。确认不需要的配置后再删除，保留一份供 GUI 使用；删除操作会同时移除其中的账号与密码。

如果只有一份配置却提示会话关系不明确，先正常退出并重新打开。问题反复出现时请反馈，无需删除账号配置。ctl 操作见[高级使用](advance.md#与-gui-配合使用)。

## 提示存储未受保护

检查数据目录和文件权限。密码是明文，确认继续保存也不会加密或修复权限。详见[数据与隐私](privacy.md)。

## 后台未启动或版本不兼容

确认 GUI、ctl、后台和配套文件来自同一个包，并已完整安装或解压。已有旧后台时先正常停止，不要只替换单个 EXE。

ctl 的只读查询不会启动后台，需要时先执行 `sidraviactl daemon start`。GUI 会自行启动核心。

## 反馈问题

到 [Issues](https://github.com/CaelestisAstesia/sidravia/issues) 提供版本、系统、安装版或便携版、GUI 或 ctl 模式，以及复现步骤和错误提示。也请说明是否使用 VPN、代理、TUN 或其他认证客户端。

GUI 可以在「连接与诊断」复制摘要。已经使用 ctl 时，可导出到一个尚不存在的文件：

```powershell
.\sidraviactl.exe diagnostics export --output .\sidravia-diagnostics.json
```

不要为了导出而在故障现场切换模式，这会结束当前连接。分享前检查摘要和截图，遮住账号；不要上传密码、`configurations.json` 或未经检查的 TRACE 日志、原始报文。
