# 常见问题

## 无法连接

先查看首页的错误提示，再依次检查：

- 当前网络是否使用吉林大学 Dr.Com 5.2.0 D 认证。
- 账号、密码是否正确，官方客户端及其他认证客户端是否已退出。
- 校园网络接口是否已连接。通常保留「自动选择可用网卡」；如果手动指定了网卡和 IPv4，确认它们仍然可用。
- 是否开启 VPN、代理或 TUN。可暂时关闭后重试，判断是否影响认证路由。

仍然失败时，在「设置 → 连接与诊断」刷新网络诊断，记下错误提示、错误码和发生时间。超时、服务器拒绝和协议响应异常的原因不同，请保留具体提示，不要仅记录「连接失败」。

吉林大学配置的服务端和本地端口均为 UDP `61440`。提示端口占用时，请核对占用程序及实际绑定地址；确认属于其他认证客户端后，正常退出该程序，不要直接结束不明进程。

## 认证成功，但网页打不开

认证成功表示认证连接已建立，不保证所有网站都能访问。可以依次检查：

- 打开其他网页，判断是单个网站异常，还是普遍无法访问。
- 暂时关闭 VPN、代理或 TUN 后重试。
- 在「设置 → 连接与诊断」刷新网络诊断，查看路由、认证目标和本机网络相关结果；需要时执行有限 IP 探测。DNS 问题需另行检查系统网络设置。

网络诊断与 IP 探测只能提供排查线索，不能替代实际网页访问。若问题持续，请按下文[反馈问题](#反馈问题)提供诊断摘要，并说明哪些网页可以或无法访问。

## 没有自动登录或自动重连

先区分三项设置：

- **启动时自动登录**：开启后，在下次后台启动并取得网络状态时自动认证，不会立即发起连接。
- **自动重连**：修改在下次连接时生效。需要立即应用时，请断开后重新连接。
- **开机自启**：只负责在登录 Windows 后启动程序；需要自动认证时，还应开启「启动时自动登录」。

网络变化后无法恢复时，检查是否手动固定了已不可用的网卡或 IPv4。通常建议使用「自动选择可用网卡」，便于网络自持机制处理接口变化。

如果首页提示需要人工处理，请先解决相应错误，再手动连接。各项设置的详细说明见[使用指南](guide.md#自动连接与开机自启)。

## 关闭窗口后仍然在线

默认关闭窗口会隐藏到托盘，后台继续保持连接。需要断开并退出时，在托盘菜单选择「退出 Sidravia」；只想断开认证、保留程序窗口时，在首页断开即可。

可在「设置 → 启动与窗口行为」中调整关闭窗口后的行为。

## 学校公告打不开

先在首页手动打开学校公告：

- **公告窗口无法加载网页**：用浏览器访问同一学校公告网页。浏览器也打不开时，先检查网络或等待学校网站恢复；浏览器能打开、公告窗口仍失败时，检查 Microsoft Edge WebView2 Runtime 是否已安装并可用，反馈时附上具体错误提示。
- **手动能打开，但没有自动显示**：检查「设置 → 公告」中的显示频率，以及主窗口隐藏时的处理方式。「每天首次连接成功后」不会在当天每次重连时重复显示。
- **没有收到公告通知**：检查 Sidravia 的「通知提醒」是否设为「不提醒」，以及 Windows 是否允许 Sidravia 发送通知。

自动显示或通知不可用时，仍可从首页尝试手动查看公告。

## GUI 与 CTL 提示模式冲突

图形界面和 CTL 使用不同的后台模式，不能同时控制同一认证后台。

- **图形界面切换到 CTL**：先在托盘菜单选择「退出 Sidravia」，再启动命令行后台。
- **CTL 切换到图形界面**：在程序目录打开 PowerShell，执行 `.\sidraviactl.exe daemon stop`，再打开图形界面。

切换会断开当前连接，原 Session ID 也会失效。图形界面运行期间，CTL 只有 `daemon status` 可以跨模式查询后台状态。完整步骤见[命令行高级使用](advance.md#与-gui-配合使用)。

## 提示多个配置或会话关系不明确

图形界面目前只管理一份连接配置。提示存在多个配置时，先备份账号配置文件，再正常退出图形界面，按[命令行高级使用](advance.md#与-gui-配合使用)切换到 CTL，使用 `config list` 和 `config show <configuration-id>` 核对。

如需继续使用图形界面，请确认要保留的一份配置，再决定是否删除其他配置。**删除配置会同时删除其中保存的账号与密码**；仍需使用多配置时，可继续通过 CTL 管理。

如果只有一份配置却提示会话关系不明确，先正常退出并重新打开。问题反复出现时，请保留错误提示并反馈，无需先删除账号配置。

## 提示存储未受保护

这表示程序未能确认或建立所需的数据存储保护。请先检查数据目录和文件权限，具体说明见[数据与隐私](privacy.md#账号与密码)。

**密码以明文保存。** 选择继续保存，不会加密密码，也不会自动修复权限；请了解提示中的风险后再决定是否继续。

反馈此问题时，可以提供错误提示和存储位置说明，不要上传账号配置文件。

## 后台未启动或版本不兼容

确认 GUI、CTL、后台及配套资源来自同一个发行包，并已完整安装或解压。不要只替换单个 EXE，也不要混用不同版本的程序文件。

如果仍有旧后台运行，请先通过原版本正常退出：GUI 从托盘菜单选择「退出 Sidravia」；独立后台使用原包中的 `sidraviactl daemon stop`。退出后再启动新版。

GUI 会自行启动配套核心。使用 CTL 时，只读查询不会自动启动后台；可在程序目录打开 PowerShell，先执行：

```powershell
.\sidraviactl.exe daemon start
.\sidraviactl.exe daemon status
```

若提示模式冲突，请按上文[模式切换说明](#gui-与-ctl-提示模式冲突)处理。问题持续时，保留具体错误提示，并说明是否刚更新版本、移动目录或切换使用方式。

## 反馈问题

请在 [Issues](https://github.com/CaelestisAstesia/sidravia/issues) 提供：

- Sidravia 版本、操作系统及架构。
- 安装版或便携版，以及使用 GUI 还是 CTL。
- 复现步骤、预期结果、实际错误提示及发生时间。
- 是否使用 VPN、代理、TUN 或其他认证客户端。
- 是否刚升级、移动程序目录，或修改网卡绑定。

GUI 用户可在「设置 → 连接与诊断」复制诊断摘要。已经使用 CTL 且后台可连接时，可在程序目录打开 PowerShell，将诊断导出到尚不存在的文件：

```powershell
.\sidraviactl.exe diagnostics export --output .\sidravia-diagnostics.json
```

不要为了导出诊断而在故障现场切换 GUI/CTL 模式，这会结束当前连接。导出失败时，请保留失败提示，无需为此删除配置或重建现场。

分享前检查截图、摘要和附加材料，遮住账号；不要上传密码、`configurations.json`、未经检查的 TRACE 日志或原始认证报文。
